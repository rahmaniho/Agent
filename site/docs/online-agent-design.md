# طرح مرحلهٔ جداگانه: اجرای امن ایجنت آنلاین

این سند طراحی است، نه سرور اجراشده. ایجنت فعلی به bridge و ابزار محلی نیاز دارد. هرگز FCC محلی یا یک shell عمومی را مستقیماً در اینترنت منتشر نکنید.

## مرز اعتماد و اجزا

مرورگر با HTTPS و توکن کوتاه‌عمر کاربر به API هم‌مبدأ متصل می‌شود. API اعتبار توکن، مالک پروژه، وضعیت اشتراک، محدودیت نرخ و سهمیه را در سرور بررسی و یک job در صف خصوصی ثبت می‌کند. worker جدا از API هر job را در یک محیط ایزوله و یک‌بارمصرف برای همان کاربر اجرا می‌کند؛ هیچ داده، فایل یا فرایندی میان اجراها مشترک نیست. کلید ارائه‌دهنده در secret manager می‌ماند و هیچ کلید مدیریتی یا توکن کاربر در image، خروجی یا مرورگر قرار نمی‌گیرد. لاگ‌ها اطلاعات حساس و محتوای کاربر را به طور پیش‌فرض ثبت نمی‌کنند.

## دفاع‌های ضروری پیش از تولید

- ماشین مجازی سبک یا sandbox سخت‌شده با هویت بدون امتیاز، root filesystem فقط‌خواندنی، بدون Docker socket، capabilities محدود، seccomp و جداسازی tenant؛ خروجی‌ها جداگانه و با محدودیت حجم نگهداری شوند. container به‌تنهایی تضمین امنیت نیست.
- محدودیت سخت زمان، CPU، حافظه، دیسک، تعداد پردازه، اندازه ورودی و خروجی، هم‌زمانی و هزینهٔ مدل؛ صف دارای سقف و لغو واقعی job همراه با خاتمهٔ کل sandbox باشد.
- شبکهٔ خروجی پیش‌فرض بسته؛ فقط مقصدهای ضروری با پروکسی کنترل‌شده، DNS و IP بررسی‌شده و حفاظت در برابر SSRF، loopback، شبکه‌های خصوصی و metadata cloud. بارگذاری وابستگی‌ها و مخازن عمومی همچنان ورودی غیرقابل اعتمادند.
- ابزارهای مجاز محدود و نسخه‌بندی‌شده، نه اجرای آزاد فرمان یا دسترسی مستقیم به ماشین میزبان. اجرای کد تنها در sandbox و پس از ارزیابی مستقل تهدیدها. عملیات حساس، انتشار و دسترسی شبکه نیازمند تأیید صریح کاربر باشند.
- دسترسی فایل، نتیجه، وضعیت و لغو با بررسی مالکیت سمت سرور؛ بارگذاری فایل دارای سقف، اعتبارسنجی، اسکن و نگهداری کوتاه‌مدت. رویدادهای پیشرفت با مجوز و بدون درج اسرار تحویل شوند.
- چرخه عمر secret و چرخش کلید، رصد هزینه و خطا، لاگ ممیزی بدون اطلاعات حساس، حذف دوره‌ای داده، backup، پاسخ به حادثه و تست نفوذ. در قطع ارتباط/انقضا، sandbox باید خاتمه یابد.

## قرارداد پیشنهادی و مراحل

`POST /api/jobs` با project ID و وظیفه؛ `GET /api/jobs/:id` برای وضعیت و نتیجه؛ `POST /api/jobs/:id/cancel` برای لغو. تمام مسیرها نیازمند احراز هویت، کنترل مالکیت و محدودیت نرخ هستند؛ شناسهٔ job به تنهایی مجوز نیست. صف و worker به اینترنت عمومی گوش نمی‌دهند. API داخلی و worker باید درخواست‌ها را idempotent و در برابر تحویل تکراری مقاوم کنند.

ابتدا مدل تهدید و سیاست ابزارها تصویب شود؛ سپس نمونهٔ آزمایشی بدون شبکه و بدون دادهٔ واقعی ساخته شود؛ بعد آزمون جداسازی دو کاربر، فرار sandbox، SSRF، مصرف منابع، توقف، مجوز، لو رفتن secret و خطاهای صف انجام شود. فقط پس از بازبینی امنیتی مستقل، پایلوت محدود و پایش هزینه به تولید برسد. انتخاب ارائه‌دهنده و هزینه عملیاتی نیاز به تصمیم جداگانه دارد.
