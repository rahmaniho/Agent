# ECC Playbook — وب‌اپ راهنمای «چه چیزی برای چه کاری»

وب‌اپ فارسی/RTL که کاتالوگ ریپوی [affaan-m/ecc](https://github.com/affaan-m/ecc) را به **نیاز واقعی بازدیدکننده** نگاشت می‌کند.
برای هر خدمت (ساخت سایت، داشبورد، API، امنیت، کارایی، ایجنت، …) مسیر گام‌به‌گام، ابزارهای مربوطه و **پرامپت‌های آماده برای کپی** را نشان می‌دهد.

وب‌اپ استاتیک بدون نیاز به build هنگام اجرا؛ کد Supabase برای مرورگر از پیش bundle شده و برای بازسازی آن به npm نیاز است.

**آنلاین:** <https://rahmaniho.github.io/Agent/>

## اجرا در محل

```bash
node site/serve.mjs              # http://localhost:4173
node site/serve.mjs --port 8080
```

یا هر سرور استاتیک دیگر با ریشهٔ `site/`:

```bash
python3 -m http.server -d site 4173
```

> چون داده‌ها با `fetch` بارگذاری می‌شوند، باز کردن مستقیم `index.html` با `file://` کار نمی‌کند؛ از سرور محلی استفاده کنید.

## استقرار روی GitHub Pages

`.github/workflows/pages.yml` با هر push روی `main` که `site/**` را تغییر دهد اجرا می‌شود:

1. اعتبارسنجی: `node --check` روی JS، پارس شدن JSONها، و بررسی اینکه هر اسکیل/دستور/agent ارجاع‌داده‌شده در `playbooks.json` در `data.json` وجود دارد.
2. آپلود پوشهٔ `site/` به‌عنوان artifact و انتشار با `actions/deploy-pages`.

تنظیم لازم در ریپو: **Settings → Pages → Source: GitHub Actions**.
دامنهٔ اختصاصی (اختیاری): یک repository variable به نام `PAGES_CUSTOM_DOMAIN` بسازید؛ ورک‌فلو فایل `CNAME` را خودکار اضافه می‌کند.


## بازتولید کاتالوگ

```bash
git clone --depth 1 https://github.com/affaan-m/ecc.git /tmp/ecc
node site/tools/gen-data.mjs --src /tmp/ecc --out /path/to/private/data.json
```

مسیر خروجی باید خارج از مخزن باشد؛ فایل جدید با دسترسی محدود ساخته می‌شود و فایل موجود بازنویسی نمی‌شود. اسکریپت `name`/`description` را از frontmatter فایل‌های `skills/*/SKILL.md`، `commands/*.md` و `agents/*.md` می‌خواند.
ارجاع‌های نام در `playbooks.json` باید با همین نام‌ها تطبیق داشته باشند؛ ورک‌فلو Pages این را خودکار بررسی می‌کند.

## امکانات اپ

- **روتر هش‌محور** با ویوهای مستقل و لینک مستقیم: `#/services`، `#/s/website`، `#/library`، `#/install`
- **کتابخانهٔ نمونه و محتوای اشتراکی** با جست‌وجوی نرمال‌شده (ی/ک فارسی-عربی)، تب اسکیل/دستور/agent و فیلتر «فقط ابزارهای مسیرها»
- **پالت دستور** با `Ctrl/Cmd+K` یا `/` و پیمایش با کلید
- **کپی با یک کلیک** (clipboard + فالبک `execCommand`) برای نام‌ها، دستورها و پرامپت‌ها
- **PWA**: `manifest` + سرویس‌ورکر با استراتژی «شبکه اول» برای داده و «کش اول» برای دارایی‌ها
- **دسترسی‌پذیری**: RTL، فوکوس نمایان، `aria-current`، پرش به محتوا، `prefers-reduced-motion`
- **تم روشن/تاریک** با ذخیره در `localStorage` و به‌روزرسانی `theme-color`
- **چاپ / PDF** برای گرفتن چک‌لیست مسیر

## Agent Studio و Free Claude Code

صفحهٔ اصلی به داشبورد فارسی Agent Studio تبدیل شده است. مسیرهای ECC، کتابخانه، جست‌وجو و راهنمای نصب قبلی همچنان در دسترس‌اند. بخش «Free Claude Code» راهنمای شروع محلی را نشان می‌دهد؛ این سایت استاتیک است و به خودی خود سرور FCC یا یک مدل هوش مصنوعی را اجرا نمی‌کند. سورس FCC به صورت snapshot در `../free-claude-code/` قرار دارد و تحت AGPL-3.0-only منتشر شده است.

## حساب و فضای شخصی

بخش `#/workspace` از Supabase Auth و جدول `workspace_notes` استفاده می‌کند. کلید publishable در `src/workspace.js` عمداً عمومی است؛ محرمانگی به سیاست‌های RLS در `db/001_workspace_notes.sql` وابسته است. رمز کاربر و توکن در مخزن ذخیره نمی‌شوند. سرویس Supabase برای این استودیو مستقل است. برای بازسازی فایل مرورگر پس از تغییر سورس: `cd site && npm ci && npm run build:workspace`. مجوز SDK در `LICENSE-SUPABASE` است.

## اجرای ایجنت روی دستگاه شخصی

FCC Admin طبق طراحی بالادستی فقط محلی است و نباید مستقیماً به اینترنت باز شود. پس از نصب FCC، تنظیم provider و نصب Codex، `fcc-server` را در دستگاه خود اجرا کنید. سپس در ترمینالی دیگر:

```bash
node site/serve.mjs --host 127.0.0.1 --port 4173 --fcc-local
```

آدرس چاپ‌شده را **در مرورگر همان دستگاه** باز و به Free Claude Code بروید. در صورت تغییر پورت FCC از `--fcc-port` استفاده کنید (پیش‌فرض 8082). پروکسی محدود فقط با انتخاب صریح این گزینه و اتصال loopback کار می‌کند و قابلیت اجرای دستور و تغییر فایل دارد؛ این حالت را در محیط اشتراکی یا برای کاربران نامطمئن اجرا نکنید. فهرست ۲۵ جلسه اخیر در FCC، بازکردن مجدد جلسه، ارسال و توقف در استودیو در دسترس است. درخواست‌های تأیید، انتخاب مدل و امکانات کامل در Admin خود FCC انجام می‌شوند. نسخه Vercel فقط فضای کار و راهنما را ارائه می‌دهد و نمی‌تواند به FCC محلی کاربر وصل شود؛ برای اجرای ابری به طراحی ایزوله و احراز هویت جداگانه نیاز است.

## طرح‌ها و پنل مدیریت

طرح‌های رایگان و پلاس پیش از ورود نمایش داده می‌شوند و ساخت حساب رایگان است. بدون اشتراک، ۱۶ مورد از ۳۱۴ مهارت، ۵ دستور از ۹۸، ۴ دستیار از ۷۱ و ۲ متن از ۳۸، به‌همراه عنوان و توضیح کوتاه مسیرها در دسترس‌اند؛ این اندازه‌گیری تقریباً ۵٪ محتوای کاتالوگ است نه ۵٪ همهٔ بخش‌های برنامه. نمایش صفحهٔ نصب و FCC در رابط برای مشترکان باز است، ولی حساب، یادداشت‌ها و نمای مسیرها برای کاربران رایگان هم در دسترس‌اند. قفل صفحه‌های نصب و FCC صرفاً در رابط است و پل محلی روی دستگاه کاربر از نظر فنی با اشتراک سرور محدود نمی‌شود. اشتراک پلاس یک‌ساله ۹۹۰٬۰۰۰ تومان است. پرداخت به کارت 5041-7212-1523-6069 به نام حسین رحمانی انجام می‌شود. کاربر پس از ساخت حساب، شناسه پرداخت، تاریخ و ساعت محلی واریز، ایمیل پرداخت‌کننده و تصویر فیش را ثبت می‌کند. درخواست و فیش در صف مدیر قرار می‌گیرند؛ دکمهٔ اختیاری ایمیل، پیام آماده بدون پیوست را باز می‌کند و خود کاربر باید آن را ارسال کند. هیچ ایمیل خودکار، درگاه آنلاین یا تأیید خودکار پرداخت وجود ندارد؛ مدیر پرداخت را جداگانه بررسی و اشتراک را فعال می‌کند. پنل حداکثر ۵۰۰ حساب تازه را نمایش می‌دهد و درخواست‌ها را صفحه‌بندی می‌کند.

در `db/003_manual_purchase.sql` و `db/004_payment_details.sql` محتوای کامل فقط از طریق `studio_premium_catalog` با بررسی عضویت فعال یا نقش مدیر قابل دریافت است؛ جدول‌های کاتالوگ و درخواست برای کلاینت مجوز مستقیم ندارند. درخواست تکراریِ در انتظار با ایندکس یکتا رد می‌شود و تأیید مدیر و فعال‌سازی در یک تراکنش انجام می‌شوند. محتوای اشتراکی در مرورگر یا سرویس‌ورکر برای استفاده آفلاین ذخیره نمی‌شود و پس از خروج یا انقضا از رابط پاک می‌شود. در صورت قطع اتصال یا خطای مجوز، برنامه به نمونه رایگان برمی‌گردد.

نسخهٔ کامل جاری کاتالوگ در جدول `studio_catalog` پایگاه داده نگهداری می‌شود و دسترسی مستقیم آن برای کاربران و ناشناس بسته است؛ تنها RPC اشتراک معتبر یا مدیر را می‌پذیرد. فایل‌های `catalog/data.json` و `catalog/playbooks.json` از درخت فعلی حذف شدند و آزمون‌ها از دادهٔ ساختگی استفاده می‌کنند. **نسخه‌های قبلی Git و منابع بالادستی متن‌باز از قبل عمومی بوده‌اند و این حذف محتوای قدیمی را محرمانه نمی‌کند.** پوشه‌های مجاز متن‌باز `kit/` و `free-claude-code/` عمداً برای نصب و رعایت شرایط مجوز حفظ شده‌اند. کاتالوگ از منابع MIT اثر Affaan Mustafa و مسیرهای فارسی ساخته شده است؛ اعلان‌ها و مجوزهای منابع حفظ شوند.

برای بازیابی یا پروژهٔ جدید، مدیر باید نسخهٔ پشتیبان خصوصی و امن کاتالوگ را از پایگاه داده فعلی تهیه و به‌صورت اداری در جدول `studio_catalog` پروژهٔ مقصد قرار دهد؛ مهاجرت‌های ۰۰۱ تا ۰۰۷ فقط ساختار را ایجاد می‌کنند و به تنهایی محتوا را برنمی‌گردانند. دسترسی، رمز و فایل پشتیبان نباید در مخزن، artifact عمومی یا مرورگر قرار گیرد. بازیابی را پیش از هر تغییر زیرساخت آزمایش کنید؛ راهنمای عملیاتی در `docs/catalog-operations.md` است.

مهاجرت `db/002_subscriptions.sql` جداول محافظت‌شده و توابع سمت پایگاه داده را ایجاد می‌کند. در مهاجرت مدیر اولیه‌ای تعریف نشده است؛ دسترسی از متادیتای قابل‌ویرایش کاربر گرفته نمی‌شود. پس از آنکه مالک، حساب مدیر مورد اعتماد را مشخص و حساب ثبت‌نام کرد، تنها فردی با دسترسی مدیریتی به پایگاه داده باید شناسهٔ همان حساب را در `public.studio_admins` وارد کند. از دادن دسترسی نوشتن این جدول به مرورگر خودداری کنید. عملیات مدیریت تنها با بررسی شناسهٔ حساب در پایگاه داده انجام می‌شوند. جدول‌ها برای کاربران و مهمان‌ها مجوز مستقیم ندارند. برای یک نسخهٔ تجاری، لازم است سیاست قیمت، مزایا، پشتیبانی، ثبت وقایع، صفحه‌بندی و پرداخت امن طراحی و آزمون شود.

دسته‌های کتابخانه بر پایهٔ ارتباط واقعی ابزارها با مسیرهای راهنما هستند؛ مواردی که هنوز به مسیری متصل نشده‌اند در «سایر ابزارها» قرار دارند و توضیح اصلی انگلیسی‌شان جداگانه قابل مشاهده است. عنوان و نیازهای همهٔ مسیرها ساده‌سازی شده‌اند، اما جزئیات فنی و متن بعضی پرامپت‌ها همچنان نیاز به بازبینی تخصصی دارند. تصویر ورودی با هوش مصنوعی تولید شده است.

## بررسی خودکار تغییرات سایت

گردش‌کار `Site CI` برای هر درخواست ادغام، برنامهٔ Node را از وابستگی‌های قفل‌شده نصب می‌کند، دستورهای JavaScript و JSON و ارجاع‌های کاتالوگ را بررسی می‌کند، یکسان بودن bundle حساب با فایل منبع را می‌سنجد و آزمون‌های رابط و پل محلی را اجرا می‌کند. گردش‌کار قدیمی Deno برای این کد مرورگری/Node و snapshot بالادستی مناسب نبود؛ این بررسی جایگزین آن شده است. این آزمون‌ها تست کامل پروژهٔ مستقل Free Claude Code یا تست سرتاسری سرویس‌های واقعی نیستند.

## ابزار ساخت متن درخواست

بخش `#/builder` یک فرم فارسی برای ساخت و کپی درخواست بر اساس نقش، هدف، زمینه، قالب، محدودیت و نمونهٔ اختیاری است. این ابزار هیچ فراخوانی مدل انجام نمی‌دهد و اطلاعات فرم را ذخیره یا ارسال نمی‌کند. هنگام بازگشت به حالت رایگان، محتوای فرم از رابط پاک می‌شود. نمایش این ابزار در رابط به پلاس محدود است، اما چون کد فرم در سایت استاتیک عمومی است، این محدودیت مانند قفل FCC صرفاً رابط است و محافظت سمت سرور محسوب نمی‌شود.

ایده‌های آموزشی از [Prompt Engineering Guide](https://github.com/dair-ai/Prompt-Engineering-Guide) نسخهٔ `57673726396dd94acb23bdb1e67f27c78ee85a8e` اقتباس و به فارسی بازنویسی شده‌اند. مشخصات و توضیح انتساب در `../kit/external/prompt-engineering-guide/` و متن کامل مجوز MIT در `LICENSE-PROMPT-ENGINEERING-GUIDE` موجود است. این ابزار وعدهٔ صحت یا نتیجهٔ مشخصی از مدل نمی‌دهد.

### فیش‌های پرداخت خصوصی

`db/005_receipts.sql` یک فضای ذخیره‌سازی خصوصی با حداکثر ۵ مگابایت و فرمت‌های JPEG، PNG و WebP می‌سازد. مجوز بارگذاری به مسیر رزروشدهٔ صاحب حساب محدود است؛ پس از ارسال، فایل برای صاحب آن و مدیران قابل خواندن است، ولی دیگر با دسترسی کاربر قابل حذف یا جایگزینی نیست. مدیر با دکمهٔ دریافت فیش پیوندی با اعتبار ۶۰ ثانیه می‌گیرد؛ داشتن پیوند در این مدت اجازهٔ مشاهده می‌دهد، پس نباید آن را به دیگران داد. این فایل‌ها و داده‌های شخصی نیازمند سیاست نگهداری و حذف عملیاتی مناسب‌اند؛ فایل نیمه‌کاره هنگام تلاش بعدی همان حساب پاک می‌شود، اما اگر هرگز دوباره تلاش نکند، پاک‌سازی مدیریتی لازم است. پسوند و نوع فایل به‌تنهایی اصالت فیش را ثابت نمی‌کنند.

برای سازگاری با نسخهٔ منتشرشدهٔ قدیمی، RPC سه‌پارامتری قبلی حذف نشده و درخواست‌های قدیمی یا ارسالی از آن ممکن است فیش نداشته باشند؛ رابط جدید فقط از RPC جدیدِ نیازمند فیش استفاده می‌کند. مدیر باید تمام پرداخت‌ها را مستقل از ارسال فرم یا تصویر بررسی کند. ایمیل خودکار یا اعلان فوری به مدیر وجود ندارد و مدیر باید صف را بررسی کند.

### ورود و درخواست اشتراک

صفحهٔ اصلی و اطلاعات طرح برای مهمان در دسترس است. فرم درخواست در صفحهٔ اصلی و مسیر `#/subscribe` دیده می‌شود؛ برای ارسال اطلاعات پرداخت و تصویر فیش باید ابتدا وارد حساب شد. درخواست و فیش خصوصی به صف بررسی مدیر ارسال می‌شوند و فعال‌سازی خودکار نیست. گزینهٔ ایمیل صرفاً برنامهٔ ایمیل کاربر را باز می‌کند و ارسال آن دستی است.

ورود و بازیابی از Supabase Auth استفاده می‌کنند؛ نشست پیش‌فرض در sessionStorage است و با انتخاب «مرا به خاطر بسپار» در localStorage نگه‌داری می‌شود. برای تولید ایمیل قابل‌اعتماد در محیط عمومی، تنظیم SMTP و سیاست‌های نرخ‌دهی و نشانی‌های بازگشت در Supabase ضروری است. در مخزن و نسخه‌های عمومی قدیمی همچنان محتوای قبلاً منتشرشده قابل دسترسی است؛ محدودیت‌های رابط به تنهایی حفاظت محتوای منتشرشده محسوب نمی‌شوند.

### راه‌اندازی ورود با گوگل

دکمهٔ گوگل از Supabase OAuth استفاده می‌کند و حساب تازه بدون اشتراک پولی ساخته می‌شود؛ فعال‌سازی پلاس همچنان فقط با مجوز سمت سرورِ مدیر انجام می‌شود. اتصال برنامه‌های گوگل به محیط توسعه به‌تنهایی ارائه‌دهندهٔ OAuth این پروژه را فعال نمی‌کند. تا زمانی که تنظیمات زیر تکمیل نشوند، دکمه پیام «هنوز فعال نشده» نشان می‌دهد و روش ایمیل همچنان در دسترس است.

1. در Google Cloud برای پروژهٔ متعلق به برنامه، صفحهٔ رضایت OAuth و یک OAuth client از نوع **Web application** بسازید. اگر برنامه در حالت Testing است، حساب‌های آزمایشی را در Google Cloud اضافه کنید و برای دسترسی عمومی الزامات انتشار/تأیید گوگل را بررسی کنید.
2. در Authorized redirect URIs، نشانی `https://asxyjxxgpfsgfmabqqdw.supabase.co/auth/v1/callback` را ثبت کنید. مبدأهای وب مورد استفاده را مطابق تنظیمات Google Cloud اضافه کنید.
3. در داشبورد Supabase همین پروژه، Authentication → Sign In / Providers → Google را باز کنید، Client ID و Client Secret همان OAuth client را مستقیماً آنجا وارد و Google را فعال کنید. کلید محرمانه نباید در مخزن، فایل فرانت‌اند یا گفتگو ثبت شود.
4. در Supabase → Authentication → URL Configuration، نشانی‌های بازگشت سایت‌های واقعی را در فهرست مجاز نگه دارید. برای این پروژه Vercel و GitHub Pages و نشانی توسعهٔ محلی تعریف شده‌اند. پس از فعال‌سازی، کل مسیر ثبت‌نام/ورود، بازگشت به فرم اشتراک، ارسال واقعی فیش و بررسی مدیر را با حساب‌های آزمایشی جداگانه بررسی کنید.

پیش از تأیید و فعال‌سازی، مدیر باید واریز را مستقل از فیش و فرم با اطلاعات بانک راستی‌آزمایی کند. ارسال درخواست یا ورود با گوگل به‌خودی‌خود اشتراک را فعال نمی‌کند. مدیر اعلان خودکار دریافت نمی‌کند و باید صف را بررسی کند.

### دسته‌بندی موضوعی

صفحهٔ اصلی برای هر یک از ۱۵ مسیر موجود یک کارت دارای آیکون دارد. انتخاب هر کارت مسیر مربوط را باز می‌کند. در کتابخانه می‌توان از کارت‌های موضوعی یا فهرست انتخاب برای محدود کردن ابزارها به نگاشت‌های همان مسیر استفاده کرد؛ «سایر ابزارها» مواردی هستند که هنوز به هیچ مسیر فعلی متصل نشده‌اند، نه یک دسته‌بندی خودکار بر اساس نام. با تغییر اشتراک، فهرست از محتوای مجاز همان حساب بازسازی می‌شود.

### توسعه پروژه‌ها و بررسی اشتراک (مهاجرت ۰۰۶)

صفحهٔ «پروژه‌های من» یک پیشنهاد قالبی بر اساس موضوع، گزینه‌های نیاز و پیش‌نیازهای مسیر می‌دهد، نه تحلیل هوشمند توضیح آزاد کاربر. نام و توضیح قابل ویرایش هستند؛ مرحلهٔ دلخواه نیز می‌توان افزود. نام، توضیح، موضوع و چک‌لیست پروژه پس از ورود در `studio_projects` با RLS مالک ذخیره می‌شود و با ورود به همان حساب در دستگاه دیگر در دسترس است؛ حداکثر ۱۰۰ پروژهٔ تازه نمایش داده می‌شود. در تعارض دو دستگاه تغییر دوم رد و اطلاعات تازه بارگذاری می‌شود. علاقه‌مندی کتابخانه فقط در مرورگر فعلی ذخیره می‌شود. سطح پیشنهادی و شرح اختصاصی فارسی برای نمونه‌های رایگان بررسی شده است و سایر موارد «ارزیابی‌نشده» هستند. یادآوری پایان اشتراک در برنامه و ۳۰ روز قبل از پایان نمایش داده می‌شود، نه به شکل ایمیل یا اعلان پس‌زمینه.

مهاجرت‌های `db/006_projects_review.sql` و `db/007_purchase_paging.sql` باید پیش از استقرار این رابط روی پایگاه مربوطه اعمال شوند. فهرست بررسی صفحه‌بندی‌شده، یادداشت داخلی مدیر، دلیل رد قابل مشاهده برای کاربر و تاریخچه تغییر اشتراک را اضافه می‌کند. تاریخچه از زمان نصب مهاجرت ثبت می‌شود و گذشته را بازسازی نمی‌کند. RPCهای قدیمی برای سازگاری حفظ شده‌اند؛ مدیران با نسخهٔ قدیمی می‌توانند بدون درج دلیل درخواست را رد کنند. پیش از بازنشسته‌سازی آنها نسخه‌های منتشرشده را هماهنگ کنید. تغییرات پایگاه داده را روی محیط آزمایشی، با دو حساب متفاوت و یک مدیر، آزمون کنید؛ تأیید فیش همچنان دستی است.

محتوای پولی جدید باید فقط با دسترسی مدیریتی در پایگاه داده یا فضای خصوصی نگهداری شود؛ تنها نمونه‌های مجاز عمومی باشند. تاریخچهٔ Git و منابع بالادستی از قبل عمومی‌اند و قابل محرمانه‌سازی مجدد نیستند. از کلید مدیریتی در مرورگر یا مخزن استفاده نکنید. طرح پیشنهادی اجرای ایجنت در `docs/online-agent-design.md` است؛ این طرح سرور اجرایی نیست.

ابزار `tools/gen-data.mjs` برای تولید کاتالوگ کامل به ورودی `--out` در مسیری خصوصی خارج از این مخزن نیاز دارد؛ فایل تولیدشده و پشتیبان‌هایش را عمومی نکنید.
